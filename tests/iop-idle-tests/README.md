This source-only package compares the candidate IOP idle-selection cache with the pinned implementation before that cache. It checks every kernel thread, register, semaphore and event flag, IOP RAM, allocator state, selected thread and wake cycle after authored lifecycle operations and deterministic mixed scheduling cases.

Set `PS2RECOMP_DIR` to the candidate PS2Recomp checkout and `IOP_REFERENCE_DIR` to its pre-cache `ps2xIOP` source directory. The reference kernel header/core are pinned by SHA256 after LF normalization. CMake generates differential sources only in external build scratch: the candidate kernel body remains unchanged, friend access is added only to its proof header, and the reference class is mechanically renamed. Actual candidate memory/SPU sources provide the shared support implementation. Separate executables run the four actual IOP suites and the existing adjacent `audio-clock-tests` fixture against the canonical candidate library.

Configure with CMake, build `RelWithDebInfo`, then run CTest with `-C RelWithDebInfo --output-on-failure`. Eight tests cover the exact-state comparison, audio clock, four IOP suites, and two mechanical corruption controls. Controls must detect the ready-selection failure category; crashes or unrelated exceptions fail. The optional `iop_idle_candidate --benchmark` measures one million idle selections for 32 authored sleeping threads and is a microbenchmark, not a game performance claim.

The relocated package passed all eight tests in a fresh native MSVC 19.44 x64 RelWithDebInfo build: 48,299 exact kernel checks, 97 audio-clock checks, both category-specific corruption controls, and all four canonical IOP suites. The controls detected omitted invalidation after 93 checks and the incorrect wake equality after 67 checks. No disc images, retail code, captured memory, generated game catalog or binaries are included. Linux and other toolchains have not been validated.
